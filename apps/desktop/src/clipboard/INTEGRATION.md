# Durable text clipboard history integration

Implemented independently in `src-tauri/src/clipboard_history.rs`, `src/providers/clipboard.ts`, and `src/clipboard/ClipboardSettings.tsx`; no shared application, stylesheet, locale, dependency, server, or application-process edits were made by this worker.

## Root integration

1. Before the existing `start_monitor()`, call `clipboard_history.initialize(app.path().app_data_dir()?.join("clipboard-history-v1.sqlite3"))`. Handle initialization failure without aborting the app: the same managed history instance retains the error for Settings and refuses capture rather than falling back to volatile storage. Start the monitor and manage the instance as before.
2. Register `get_clipboard_history_settings`, `set_clipboard_history_retention`, `set_clipboard_history_entry_pinned`, and `get_clipboard_history_entry_text` alongside all existing clipboard commands. Add explicit `NSPasteboard` and `NSArray` features to the existing objc2 AppKit/Foundation dependencies; they currently compile via arboard's feature unification.
3. Mount `<ClipboardSettings onChanged={(state) => setClipboardEnabled(state.enabled)} />` in the clipboard preferences section. It owns native state loading, toggle/clear confirmation, retention selection, counts, persistence failures, and operation-specific retries. It uses existing preference/switch classes. It emits the existing `prism:clipboard-history-setting-changed` event after successful mutations.
4. Use native SQLite consent as authoritative; remove startup enablement writes sourced from browser preferences. Reading the existing `getClipboardHistoryEnabled` remains compatible.
5. To preserve pin metadata, use `searchDurableClipboardHistory` from `providers/clipboard.ts`, or extend the legacy mapper. Its shape is `{id, content, capturedAt, pinned}`. The native search shape remains `{id, text, capturedAtMs}` plus `pinned`; previews remain limited to 500 Unicode characters. Existing copy/paste/delete/clear command names and arguments are preserved.
6. For root-owned actions, call `setClipboardHistoryEntryPinned(id, pinned)` and refresh the list. For save-as-snippet, call `getClipboardHistoryEntryText(id)` to obtain the full original text; never save the search preview as the snippet body. Root owns adding item actions and any list refresh/event treatment.
7. Add the new English localization keys listed in `localization-keys.json` to shared `locales/messages.json`; that shared file was intentionally not edited. All visible component copy uses existing `t()` and locale updates.

## Behavior and bounds

- Initially disabled. Empty schema/settings may be created at startup, but no clipboard text is collected or persisted before consent. Consent and retention persist in SQLite.
- Stores text only, up to 1,000 entries and 128 KiB UTF-8 per entry. Copying duplicate text updates recency while retaining the stable ID and pin. Search returns pins first, then newest entries, and scans rows incrementally with Unicode-insensitive matching.
- Retention choices are 1, 7, 30 (default), and 90 days. Unpinned entries expire on startup, search/full-text reads, retention changes, and approximately once per minute while monitoring. Pins survive expiry and capacity eviction. If all 1,000 entries are pinned, additional distinct text is skipped and Settings explains how to free a slot.
- Disable stops capture and atomically deletes every saved entry including pins; clear deletes every entry while preserving enablement. Neither changes the current system clipboard. IDs are never reset after deletion. Shortening retention and disabling/clearing require explicit confirmation in the component.
- Mutation failures are returned and shown. A failed disable still stops this process's capture; its error explicitly warns deletion did not persist and asks for a disable retry before restart. A failed transaction does not silently mutate the stored collection. UI notification failures do not become destructive-operation retries.
- SQLite uses FULL synchronous commits, DELETE journaling, secure_delete, and a 0600 database on Unix. These are local persistence and ordinary deletion measures, not encryption or secure erasure guarantees for backups/filesystem snapshots.
- On macOS, existing objc2 dependencies read NSPasteboard type markers before text and compare changeCount afterward, rejecting torn reads. Concealed, transient, autogenerated, private, and known password-manager markers are excluded, in addition to existing obvious-secret heuristics. Unmarked sensitive text can still be captured.
- Monitoring polls at 650 ms and establishes a baseline after enable, clear, or delete; it does not immediately recapture the current clipboard after destructive operations. Fast clipboard changes between polls can be missed. Generation checks reject an in-flight capture after a destructive operation.

## Behavioral references

The [Raycast Clipboard History manual](https://manual.raycast.com/clipboard-history) describes pin/delete/save-as-snippet actions and selectable history retention; this slice follows those interaction ideas for bounded text history. The [Raycast Clipboard API](https://developers.raycast.com/api-reference/clipboard) documents concealed clipboard content being excluded from history. No Raycast source code was copied; images, OCR, rich text, files, app exclusions, and unlimited retention are outside this slice.
