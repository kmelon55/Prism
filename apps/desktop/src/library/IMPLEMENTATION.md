# Library browsing and dynamic entry execution

The library now keeps the last successful file results visible during refresh, supports keyboard selection and file type filters, and displays bounded metadata/text/raster previews. Quicklinks with a query argument and snippets with date/time/clipboard placeholders open a compact preview form before execution.

## Root integration

The current shared tree already contains root's registration of `library_preview_file`, `library_prepare_entry`, and `library_run_entry`, plus the App import and dynamic entry wiring.

```tsx
import { LibraryRunDialog, needsLibraryRun, type LibraryRunAction } from "./library/LibraryRunDialog";

// From an explicit library action, find the current saved entry.
// Existing entries with no supported placeholders keep library_entry_action.
if (needsLibraryRun(entry)) setLibraryRun({ entry, action });

<LibraryRunDialog
  entry={libraryRun.entry}
  action={libraryRun.action} // "open" | "copy" | "paste"
  nativeRuntime={nativeRuntime}
  onClose={() => setLibraryRun(null)}
  onComplete={action => { /* clear dialog; toast copy or dismiss after open/paste */ }}
/>
```

Suspend root palette keyboard handling while this dialog is mounted, as for other full command surfaces. The component focuses its query field (or close button for snippets), traps Tab, consumes Escape, and never executes on mount. LibraryPanel renders it as its sole surface while an entry is running.

`searchFiles(query, offset = 0, limit = 40, fileType = "all")` adds an optional fourth parameter. Values are `all`, `folder`, `text`, `image`, and `document`. Native `library_search_files` accepts optional `fileType`; old callers remain compatible. Filtering occurs before total/pagination.

`library_preview_file({ id })` returns `FilePreview`: `id`, `name`, `path`, `isDirectory`, `extension`, `size` (bytes), `modifiedAt` (epoch milliseconds or null), `kind` (`text`, `image`, `directory`, `unsupported`), `text`, `imageDataUrl`, `truncated`. The UI never submits `path` for file actions or previews.

`library_prepare_entry({ id, query? })` returns `{ token, value }`. `library_run_entry({ id, action, token })` consumes the token and rechecks the saved entry. The token stores the exact resolved preview, expires after five minutes, is single use, and cannot be reused after failed execution. Refreshing the preview provides a new token. Inactive snapshots are bounded to 32 per session.

## Behavior and bounds

- Search input Arrow Up/Down focuses the file list. In the list, Arrow Up/Down, Home and End change selection; Enter opens the selected file. A click selects; double-click opens; explicit open/reveal/copy buttons remain available.
- Pending or failed replacement searches retain the previous page but disable actions until results correspond to the current query/filter/root revision. Refresh preserves selection by ID where possible. Removed selections fall back to the first new result. Old search and preview promises cannot overwrite current state.
- Search-issued file IDs are opaque session tokens stored in a bounded 4096-entry registry. Every action and preview resolves the token, reloads authorized roots, canonicalizes containment, and rejects removed roots, traversal, empty relative paths and symlink components.
- Unix preview reads walk components using directory descriptors with `O_NOFOLLOW`, `O_CLOEXEC` and `O_NONBLOCK`. Only regular files and directories are accepted, so named pipes do not hang preview reads. Root removal cannot race a preview read because the library lock covers validation and the bounded read.
- UTF-8 text previews read at most 64 KiB plus one byte; they handle a multibyte character cut at the boundary and reject binary/control content. HTML/XML are plain text in React `<pre>`, never executable markup.
- PNG/JPEG/WebP inputs are limited to 2 MiB, 4096 pixels per dimension and 64 MiB decoder allocation, then re-encoded as PNG thumbnails at most 720×720. SVG and unsupported image/document formats expose metadata only. File extension filtering does not promise preview support for every listed format.
- Link `{query}` is supported only in the URL query portion. Input bytes are percent-encoded, the final HTTP(S) URL is validated, and scheme/host/path/fragment substitution is rejected. Example: `https://example.com/search?q={query}`.
- Snippets support `{date}` (local `YYYY-MM-DD`), `{time}` (local `HH:mm`) and `{clipboard}` (current text). Replacement happens once, so clipboard text containing placeholders remains literal. Expanded output is limited to 128 KiB. Unix uses OS local time; the non-Unix fallback currently uses UTC.
- Existing save failure preservation, unsaved edit choices, and explicit deletion confirmation remain. Failed deletion retains the confirmation and retries that deletion explicitly.
